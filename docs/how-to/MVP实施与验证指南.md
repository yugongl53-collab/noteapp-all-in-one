# MVP 实施与验证指南

## 1. 用途

本文档为后续 vibe coding 提供建议顺序和可执行的验证重点。当前仓库没有业务代码；产品范围和技术栈已经确认，实施时以[产品需求文档](../product/产品需求文档.md)和[技术栈 ADR](../adr/0001-采用原生Android技术栈.md)为准。

## 2. 前置条件

- 使用 Android Studio 稳定版及其内置 JDK，Android SDK 已安装 API 37、Build Tools 和 Platform Tools。
- 由用户通过 SDK Manager 安装至少一个 API 31 或更高版本系统镜像并创建手机竖屏 AVD；准备一台 Android 12 或更高版本实体手机验证后台行为。
- 创建应用工程时设置名称“一站笔记”、`applicationId = com.yuncun.noteapp`、`minSdk = 31`、`compileSdk = 37` 和 `targetSdk = 37`，并提交 Gradle Wrapper。
- 用户创建并自行保管 release keystore；密钥文件和密码不得提交 Git。
- 已准备至少一个真实学期的名称季节、开始日期、结束日期和课程周次样例。
- 开发环境能通过 Gradle Wrapper 运行原生 Android 最小示例和自动化测试，不依赖全局 Gradle。
- 已批准 Room、DataStore、Navigation Compose、ViewModel、Coroutines 和 kotlinx.serialization；Gradle 首次同步下载它们前由用户确认网络访问。
- 后续引入任何依赖前，先说明该依赖能简化的代码和维护成本，再由用户决定是否安装。

## 3. 建议实施顺序

### 阶段一：本地数据基础与灵感闭环

实现固定事件性质、灵感的本地存储、快速输入、列表、编辑和 30 天回收站。

验证重点：

- 空正文不能保存。
- 标签在同一灵感中去重。
- 应用重启后数据仍存在。
- 保存失败不丢失输入，删除必须确认。
- 移入回收站后常规列表不可见，30×24 小时内可以恢复或手动永久删除，到期后自动清理。

### 阶段二：学期、普通事件、课程与双日程视图

先完成学期周次、普通事件和课程的日期展开逻辑，再制作课表式周视图与横向事件视图，避免界面先行掩盖时间规则错误。

验证重点：

- 学期标准名称、学期第 1 周和寒暑假边界正确。
- 循环普通事件在所选星期正确出现，单次普通事件只在指定日期出现。
- 课程入口与普通事件入口分开，课程固定属于学习类，并只在所属学期的上课周闭区间出现。
- 课程卡片同时显示课程名称和地点。
- 前后切周、返回本周结果正确。
- 结束时间不晚于开始时间时拒绝保存。
- 重叠事件被提醒且都能看见。
- 横向事件视图隐藏已结束事件、标记下一个事件，并且周常规则只展开本周。
- 两种视图不能直接编辑事件。
- 普通事件默认提前 5 分钟、课程默认提前 25 分钟提醒，均可逐项关闭或修改。
- 权限被拒绝时日程仍能保存并明确显示未提醒；提醒时间已过但事件尚未开始时立即提醒一次。
- 修改、停用、删除、时区变化和学期调整后，旧提醒被取消且未来提醒按新规则重建。

### 阶段三：事件池与随机抽取

实现事件池维护、启用过滤、空状态和等概率抽取，然后将结果连接到番茄钟启动参数。

验证重点：

- 结果只来自启用项目。
- 空池不崩溃，并引导添加。
- 停用和删除立即影响候选集合。
- 抽中结果携带正确事件性质。

### 阶段四：番茄钟与时间记录

分别实现纯工具定位的番茄钟专注计时，以及独立的时间记录手动录入、历史回溯、永久删除和重叠校验功能。

验证重点：

- 番茄钟作为纯工具运行，计时结束不生成时间记录，不影响统计数据。
- 番茄钟默认专注/休息 25/5 分钟，可分别调整到 1–180 和 1–60 分钟，阶段之间必须由用户确认开始。
- 番茄钟切到后台再返回后，剩余时间依据真实时间正确计算。
- 进程终止或设备重启后，下次打开按截止时间恢复；已过期阶段只显示完成，不补发过期提醒。
- 时间记录支持手动填写事件名称、事件性质和起止日期时间，允许选择过去日期。
- 相邻记录可保存，重叠记录不可保存。
- 删除确认明确说明不可恢复；删除后记录、统计时长和仅由该记录产生的名称快捷项都不存在。
- 名称快捷选项只填充名称，不覆盖用户填写的其他参数，且不阻止输入新名称。

### 阶段五：日周排行榜与整体打磨

基于时间记录分别生成事件性质排行榜和事件名称排行榜，确保精确时长是唯一事实来源。

验证重点：

- 示例数据的五类时长、事件名称聚合和其他时长可人工复算。
- 跨日期记录按日边界正确拆分。
- 零记录时显示空状态，不生成空名次或异常数值。
- 两种排行榜均按时长降序，平局时使用规定的稳定排序。
- 页面不显示百分比、饼图、环形图或占比条，“其他”不进入排行榜。
- 修改、永久删除记录后日周结果同步变化。
- 事件性质颜色、名称和统计口径在所有页面一致。
- 夏令时切换日使用当前设备时区的实际自然日长度，“其他”不能固定按 1440 分钟计算。

### 阶段六：备份、权限与交付

实现明文 JSON 手动导入导出、提醒权限状态、导入后的提醒重建，以及用户密钥签名的本地 APK。

验证重点：

- 导出包含全部业务数据、回收站和设置，不包含活动番茄钟或系统权限，并在保存前提示明文文件含个人数据。
- 导入先完整校验再二次确认并事务性整体替换；无效版本、悬空引用、重叠记录或活动番茄钟都不能产生部分写入。
- 导入成功后取消旧提醒，并按新数据与当前权限重建未来提醒。
- 通知或“闹钟和提醒”权限被拒绝、撤销或重新授予时，界面状态和实际调度一致。
- release keystore、密码、本机 SDK 路径和生成的 APK 不进入 Git。

## 4. 最小验收数据集

建议至少准备以下本地测试数据：

- 2 条带不同标签的灵感，另有 1 条编辑后的灵感。
- 1 个秋季学期和 1 个春季学期，用于复核标准名称、周次、寒假和暑假标签。
- 2 个每周循环普通事件，其中 1 个选择多个星期。
- 2 个同一周单次普通事件，其中 2 项时间重叠，用于检查展示。
- 1 门第 3–14 周课程，包含课程名称与地点，并准备第 2、3、14、15 周检查边界。
- 五种事件性质各 1 个启用事件池项目，另有 1 个停用项目。
- 同一天五种事件性质的时间记录总计 10 小时，其中至少两条名称相同，用于复核两种排行榜与 14 小时“其他”。
- 1 条跨午夜记录，用于复核按自然日拆分。
- 1 组首尾相接记录和 1 组重叠记录，用于复核重叠边界。
- 1 条只使用一次名称的历史记录，用于复核永久删除后统计和快捷名称同时清除。
- 1 条刚移入回收站和 1 条已超过 30×24 小时的灵感，用于复核恢复与自动清理。
- 1 个默认提前 5 分钟的普通事件和 1 门默认提前 25 分钟的课程，并准备权限拒绝、提醒时间已过和时区变化场景。
- 1 个完整 JSON 备份、1 个未知新版本备份、1 个悬空引用备份和 1 个包含重叠时间记录的备份。
- 至少选择一个夏令时切换日，验证 23 或 25 小时自然日的统计与“其他”时长。

## 5. 完成定义

每个阶段只有同时满足以下条件才算完成：

1. 对应用户流程在目标 Android 设备或模拟器上可完整操作。
2. 正常、空数据、错误输入和数据持久化场景均已验证。
3. 核心规则有自动化测试，尤其是日期展开、随机候选过滤、重叠检查、提醒调度、备份导入和统计计算。
4. 用户可见行为与[产品需求文档](../product/产品需求文档.md)一致。
5. 受影响文档已同步更新，示例、路径和默认值与代码一致。

## 6. 暂不执行的工作

在用户确认 MVP 闭环前，不主动加入登录、云服务、AI、复杂重复提醒、跨端同步或可自定义事件性质。当前范围只包含番茄钟阶段结束提醒和按提前分钟数触发的课程、普通事件提醒；不得在 vibe coding 过程中顺手扩展为提醒模板、地点触发或智能提醒。
