# MVP 执行计划与验证指南

## 1. 用途与基线

本文档用于把一站笔记从产品规划推进到可安装、可验收的 Android MVP。执行者应按里程碑顺序交付；每个里程碑都必须完成实现、自动化测试、人工验收和受影响文档更新，不能只以页面能够打开作为完成依据。

产品范围以[产品需求文档](../product/产品需求文档.md)为准，页面状态以[页面与交互说明](../product/页面与交互说明.md)为准，字段和计算规则以[数据模型与统计口径](../reference/数据模型与统计口径.md)为准，测试方法和门禁以[代码测试规范](../reference/代码测试规范.md)为准，工程选型以[技术栈 ADR](../adr/0001-采用原生Android技术栈.md)为准。本文档只定义执行顺序，不重复这些事实来源。

当前已完成 M0 工程骨架、M1 数据层与公共规则和 M2 灵感闭环。Gradle Wrapper、单元测试、Lint、Debug 构建与仪器测试编译均可运行；M3 至 M7 的业务页面仍是占位页，不应把目标能力描述为当前可用界面。

## 2. 成功标准

MVP 只有满足以下条件才可交付：

1. 灵感、日程、课程、事件池、番茄钟、时间记录、统计和备份八条流程均可在 Android 12 或更高版本手机上完成。
2. 应用重启、进程终止和设备重启后业务数据不丢失，活动番茄钟按真实截止时间恢复。
3. 日期展开、记录重叠、随机候选过滤、提醒调度、备份导入和统计计算都有自动化测试。
4. 权限被拒绝、数据为空、输入无效和导入失败等边界状态有明确反馈，不产生部分写入或错误成功状态。
5. Debug APK 可由 Gradle Wrapper 重复构建；Release APK 可用用户保管的密钥签名，密钥和本地路径不进入 Git。
6. README、开发命令、页面行为、默认值、备份格式与实际代码一致。

当前不设没有依据的日历工期。完成速度取决于执行人数、真机条件和 UI 反馈；推进依据是阶段出口，不是预估日期。

## 3. 前置条件

- 使用 Android Studio 稳定版及其内置 JDK，Android SDK 已安装 API 37、Build Tools 和 Platform Tools。
- 用户通过 SDK Manager 安装至少一个 API 31 或更高版本系统镜像，并创建手机竖屏 AVD。
- 准备一台 Android 12 或更高版本实体手机，验证通知、提醒、后台计时、省电策略和重启恢复。
- 工程使用名称“一站笔记”、`applicationId = com.yuncun.noteapp`、`minSdk = 31`、`compileSdk = 37`、`targetSdk = 37`，并提交 Gradle Wrapper。
- 用户创建并自行保管 release keystore；密钥、密码、`local.properties` 和 APK 不提交 Git。
- 准备至少一个真实学期样例，以及第 9 节的最小验收数据集。
- 已批准 Room、DataStore、Navigation Compose、ViewModel、Coroutines 和 kotlinx.serialization。首次联网下载依赖前由用户确认网络访问。
- 引入批准名单之外的依赖前，先说明能减少的代码、维护工作和简化程度，再由用户决定是否采用。

## 4. 执行顺序与工作方式

里程碑按 `M0 → M1 → M2 → M3 → M4 → M5 → M6 → M7 → M8` 推进。M2 完成后，M3 和 M5 的领域逻辑可以在不修改同一文件的前提下并行，但合并与验收仍按编号进行；M7 必须等待所有持久化模型稳定，M8 必须等待全部功能里程碑完成。

| 里程碑 | 交付主题 | 主要依赖 | 阶段出口 |
| --- | --- | --- | --- |
| M0 | Android 工程骨架 | 现有规划 | Wrapper 可构建、测试、Lint |
| M1 | 数据与公共规则 | M0 | Schema、DAO、日期和重叠测试通过 |
| M2 | 灵感闭环 | M1 | 新增、编辑、回收站、清理可用 |
| M3 | 学期、日程、课程和双视图 | M1、导航骨架 | 日期展开与两种视图一致 |
| M4 | 日程提醒与权限 | M3 | 调度、取消、重建和权限状态一致 |
| M5 | 事件池与番茄钟 | M1、导航骨架 | 随机抽取与计时恢复可用 |
| M6 | 时间记录与统计 | M1 | 重叠、排行榜和“其他”正确 |
| M7 | JSON 备份与恢复 | M2 至 M6 | 完整校验、事务替换、提醒重建通过 |
| M8 | 全链路验收与 APK | M0 至 M7 | 自动化门禁、真机回归、签名交付通过 |

每项功能固定采用以下节奏：

1. 把需求转换为正常、边界和失败用例。
2. 先实现不依赖界面的领域规则与测试，再接 Room、ViewModel 和 Compose。
3. 页面同时覆盖加载、空数据、成功和失败状态。
4. 在模拟器执行用户流程，涉及系统行为时补充实体手机验证。
5. 同步用户可见行为、公共接口、配置或命令所影响的文档。
6. 运行当前阶段门禁并提交职责单一的 Conventional Commit。

## 5. 里程碑任务

### M0：建立 Android 工程

目标是形成后续功能可复用的构建、测试和导航基础。

- [x] 创建 Kotlin、Jetpack Compose、Material 3 单 `app` 模块项目并提交 Gradle Wrapper。
- [x] 固定应用标识、SDK 级别、工具链和竖屏配置。
- [x] 配置已批准依赖，不引入未批准依赖。
- [x] 建立按功能分包的最小目录、主题、顶层导航和占位页面，不预建未来抽象层。
- [x] 建立本地单元测试与 Android 仪器测试目录，并加入最小冒烟测试。
- [x] 更新 `README.md` 和 `AGENTS.md`，记录实际构建、测试、Lint 和安装命令。
- [x] 确认 `.gitignore` 排除 SDK 路径、密钥、构建产物和 IDE 私有文件。

目标验证命令：

```bash
./gradlew test
./gradlew lint
./gradlew assembleDebug
```

阶段出口：全新检出后，只依赖 Android Studio/SDK 和 Wrapper 即可构建 Debug APK；应用能启动并完成顶层导航。

### M1：建立数据层与公共规则

目标是固定本地唯一事实来源，避免页面各自实现日期、排序和校验。

- [x] 按数据模型实现 `Idea`、`ScheduleTask`、`AcademicTerm`、`CourseSchedule`、`EventPoolItem` 和 `TimeRecord` 的 Room 实体、DAO 与数据库。
- [x] 使用 DataStore 保存 `AppSettings` 和活动 `PomodoroSession`；系统权限只读取 Android 当前状态。
- [x] 实现固定事件性质、文本规范化、绝对时间存储和当前设备时区转换。
- [x] 实现学期名称、自然周、学期周次、假期标签、日程实例展开和稳定排序纯函数。
- [x] 实现时间记录范围校验、相邻允许与重叠拒绝规则。
- [x] 为数据库约束、事务、日期边界、跨时区和夏令时场景编写测试。

M1 最小验证命令：

```bash
./gradlew testDebugUnitTest
./gradlew assembleDebugAndroidTest
./gradlew connectedDebugAndroidTest
```

前两条命令不需要设备；第三条必须连接 API 31 或更高版本的模拟器或实体手机。预期结果是纯 Kotlin 规则测试通过、仪器测试 APK 编译成功，并在设备上完成 Room 外键/重叠/重启与 DataStore 重建用例。

阶段出口：公共规则不依赖 Compose 即可测试；数据库重启后数据一致；同名学期、重叠学期和悬空引用不能写入。

### M2：完成灵感闭环

目标是交付第一条端到端流程，验证 UI、状态管理与 Room 的连接方式。

- [x] 实现今日页快速输入、灵感列表、编辑页和回收站。
- [x] 实现正文去空白校验、标签去重和按最后更新时间倒序。
- [x] 实现移入回收站、恢复、手动永久删除和 `30×24` 小时到期清理。
- [x] 保存失败时保留输入并反馈原因；删除前二次确认。
- [x] 覆盖加载、空状态、成功、校验失败和持久化失败状态。

阶段出口：应用重启后内容仍存在；普通列表不显示已删除灵感；刚删除的内容可恢复，过期内容不可恢复；核心规则和 DAO 测试通过。

#### M2 使用与验证

M2 适合随手记录临时想法，并在误删后于保留期内恢复。前置条件是使用 API 31 或更高版本的模拟器或手机安装 Debug APK；功能完全使用本地 Room 数据库，不需要账号、网络或额外权限。

最小示例：打开应用，在“今日”页输入正文 `整理 Android 学习清单`，标签输入 `学习，计划，学习` 后点击“保存灵感”。进入底栏“灵感”，预期新卡片位于顶部且标签显示为 `学习 · 计划`；编辑后更新时间和排序随之更新。确认“移入回收站”后，普通列表不再显示该卡片；在回收站点击“恢复”可回到列表，点击“永久删除”则必须再次确认且无法恢复。

验证命令：

```bash
./gradlew testDebugUnitTest
./gradlew assembleDebugAndroidTest
./gradlew connectedDebugAndroidTest
./gradlew lint
./gradlew assembleDebug
```

前三类自动化测试分别验证输入与状态规则、Room/Compose 测试包编译和设备上的 DAO/页面行为。`connectedDebugAndroidTest` 需要已连接的 API 31 或更高版本设备；其余命令不需要设备。还应在应用重启后确认已保存灵感仍存在，并用固定测试验证恰好到达 `30×24` 小时的记录已被清理。

### M3：完成学期、日程、课程与双视图

目标是实现计划日程主流程，并与实际时间记录完全分离。

- [ ] 实现学期列表、创建、编辑和删除约束。
- [ ] 分别实现普通事件和课程的配置入口、列表、表单与删除确认。
- [ ] 实现普通事件每周循环和单次规则，课程按学期及闭区间周次展开。
- [ ] 实现课表式周视图，支持切周、返回本周、重叠可见和学期/假期标签。
- [ ] 实现本周横向事件视图，过滤已结束实例并标记“进行中”和“下一个事件”。
- [ ] 实现各实体独立的历史名称快捷选项，选择名称不覆盖其他字段。
- [ ] 两种视图只负责查看与跳转，不直接编辑，不生成 `TimeRecord`。

验证重点：

- 学期第 1 周、首尾日期、寒暑假和跨边界周标签正确。
- 课程只在有效学期周次和星期出现，且固定为“学习”。
- 单次事件只出现一次；循环事件只在生效日期后的所选星期出现。
- 无效时间范围拒绝保存；重叠日程提示但允许保存且全部可见。
- 事件流只展开本周，隐藏已结束事件，并列最早未来事件均可标记为“下一个事件”。

阶段出口：两种日程视图对同一份数据结果一致，日期展开和主要页面测试通过。

### M4：完成提醒与权限适配

目标是让普通事件和课程提醒在权限、重启和数据变化后保持一致。

- [ ] 实现普通事件默认提前 5 分钟、课程默认提前 25 分钟，以及逐项关闭和修改。
- [ ] 适配通知权限与“闹钟和提醒”特殊权限，权限事实始终读取系统状态。
- [ ] 实现近期实例调度、触发后补充，以及应用启动和设备重启后的重建。
- [ ] 数据修改、停用、删除、学期调整或时区变化时，取消旧提醒并重建有效提醒。
- [ ] `remindAt <= now < startAt` 时立即提醒一次，事件已开始时不补发。
- [ ] 页面明确显示“已配置但提醒未生效”等权限受限状态。

阶段出口：调度计算测试通过；实体手机上的授权、拒绝、撤销、重启和时区变化回归通过，旧提醒不误触发。

### M5：完成事件池与番茄钟

目标是完成随机行动与专注流程，但不把计时写入统计。

- [ ] 实现事件池项目的新增、编辑、停用、删除和独立名称快捷选项。
- [ ] 只从启用项目中等概率抽取；空池返回引导状态。
- [ ] 抽取结果支持重新抽取，或只把名称带入番茄钟。
- [ ] 实现番茄钟开始、暂停、继续、重置、提前结束和阶段确认。
- [ ] 支持专注 `1...180` 分钟、休息 `1...60` 分钟，并保存最近一次设置。
- [ ] 运行时用绝对截止时间，暂停时保存剩余秒数，活动会话支持进程和重启恢复。
- [ ] 阶段结束只提醒并显示完成状态，不生成 `TimeRecord`、不自动开始下一阶段、不补发过期提醒。

阶段出口：结果始终来自启用集合；后台经过时间正确扣除；进程终止后恢复正确；统计不受番茄钟影响。

### M6：完成时间记录与日周统计

目标是以手动录入的 `TimeRecord` 作为唯一统计来源，形成复盘闭环。

- [ ] 实现时间记录新增、历史列表、编辑、永久删除和名称快捷选项。
- [ ] 允许回溯和跨日期记录；拒绝无效范围及重叠，编辑时排除自身。
- [ ] 删除使用不可恢复确认，并立即影响统计和快捷名称。
- [ ] 按当地自然日切分记录，按事件性质和名称聚合，支持日周切换。
- [ ] 两种排行榜按时长降序和规定的次级规则稳定排序，只显示精确时长。
- [ ] “其他”等于实际自然日长度减去五类有效时长，且不进入排行榜。
- [ ] 覆盖无记录、跨午夜、夏令时 23/25 小时自然日、修改和删除后的统计测试。

阶段出口：相邻记录可保存、重叠记录不可保存；固定样例可人工复算；页面没有百分比或图表；计划与番茄钟不进入统计。

### M7：完成 JSON 备份与恢复

目标是提供可验证、全有或全无的本地数据迁移。

- [ ] 使用 kotlinx.serialization 实现带 `formatVersion` 的 UTF-8 明文 JSON 导出。
- [ ] 通过系统文件选择器选择位置，导出前提示明文个人数据风险。
- [ ] 导出全部业务实体、回收站灵感与 `AppSettings`，排除番茄钟活动状态、权限、密钥和设备路径。
- [ ] 写入前完整校验版本、字段、标识、时间范围、引用、学期范围和时间记录重叠。
- [ ] 番茄钟运行或暂停时阻止导入；校验通过并二次确认后，在单个事务中整体替换。
- [ ] 导入失败回滚；成功后清理过期灵感，并按当前系统权限重建提醒。
- [ ] 覆盖完整备份、未知版本、字段错误、悬空引用、重叠记录和事务回滚测试。

阶段出口：导出再导入后数据与设置一致；任何无效备份都不产生部分写入，导入不修改系统权限。

### M8：全链路验收与 APK 交付

目标是关闭跨模块缺陷，产出可由用户安装和保管的首版 APK。

- [ ] 使用第 9 节数据执行八条核心流程和跨模块回归。
- [ ] 验证浅色、深色、字体放大、手机竖屏、空状态和长文本滚动。
- [ ] 在 API 31 模拟器完成兼容回归，在实体手机完成通知、后台、省电和重启回归。
- [ ] 运行全部单元测试、仪器测试、Lint 和 Debug/Release 构建门禁。
- [ ] 核对数据库迁移策略、备份 `formatVersion`、权限说明和隐私提示。
- [ ] 更新 README、开发命令、故障排查和当前实现状态，不把未实现规划描述为现有能力。
- [ ] 使用用户提供但不入库的 keystore 构建 Release APK，记录版本号和 SHA-256，由用户安装验收。

目标发布门禁：

```bash
./gradlew test
./gradlew lint
./gradlew connectedDebugAndroidTest
./gradlew assembleDebug
./gradlew assembleRelease
```

阶段出口：全部门禁通过，已知限制已记录，Release APK 可安装并完成冒烟流程，仓库中不存在密钥、密码、本地路径或 APK。

## 6. 测试分层

本节只说明各层在 MVP 里程碑中的职责，具体用例设计、可重复性、缺陷回归、执行顺序和结果记录要求见[代码测试规范](../reference/代码测试规范.md)。

| 层级 | 主要覆盖 | 不能替代的验证 |
| --- | --- | --- |
| 纯 Kotlin 单元测试 | 日期、排序、重叠、候选过滤、计时状态机、统计、备份校验 | Android 权限和真实后台行为 |
| Room 集成测试 | DAO、约束、事务回滚、整体导入替换 | 页面交互和真机通知 |
| Compose 页面测试 | 表单、空状态、错误状态、导航、关键文本 | 复杂计算的全部边界 |
| Android 仪器测试 | 文件适配、权限状态、数据库与页面集成 | 厂商省电策略和设备重启 |
| 实体手机人工验收 | 通知、提醒、后台、时区、重启、省电策略 | 可重复的业务计算测试 |

自动化测试必须控制时钟、时区和随机源，避免依赖执行当下时间或偶然结果。随机测试验证候选集合与基本公平性，不要求短样本严格平均。

## 7. 完成定义

每个里程碑必须同时满足：

1. 清单实现完成，没有用静态假数据替代真实持久化或系统状态。
2. 正常、空数据、错误输入、失败恢复和持久化场景已验证。
3. 新增规则有自动化测试，旧测试保持通过。
4. 模拟器可完成对应流程；涉及系统行为时已记录实体手机结果。
5. 行为与产品、交互和数据参考文档一致。
6. 受影响文档已同步，路径、命令、示例和默认值可复核。
7. `git diff --check` 通过，提交只包含当前里程碑相关内容。

未满足时保留为进行中并记录阻断原因，不能把缺少测试、权限未验或失败路径未实现降级为“后续优化”。

## 8. Git、风险与暂停条件

### Git 执行规范

- M0 至 M8 属于功能或较大改动，开始时从 `main` 创建对应分支，例如 `feat/m0-project-bootstrap`。
- 每完成一个可独立验证的部分即提交，使用 `feat:`、`fix:`、`test:`、`docs:` 等 Conventional Commits 类型。
- 多人协作开始前先拉取远端；没有远端时记录事实，不假装已经同步。
- 存在两个以上非当前分支时，并行任务使用从 `main` 派生、放在项目上一级目录的 worktree。
- 合并前运行门禁并审查范围；合并后删除本地分支和对应 worktree。
- 解决 issue 的 Pull Request 正文使用 `Closes #编号`，并说明目的、验证和文档影响；界面变化附截图或录屏。

### 风险与处理

| 风险 | 触发信号 | 处理方式 |
| --- | --- | --- |
| 提醒受权限或厂商策略影响 | 模拟器通过、真机延迟或不触发 | 显示未生效状态并在目标真机验证，不宣称绝对准点 |
| 日期规则分散 | 页面、统计和提醒结果不一致 | 暂停 UI 扩展，把规则收敛到 M1 纯函数并补测试 |
| 备份格式过早冻结 | 实体字段仍频繁变化 | M7 冻结首个 `formatVersion`，此前只维护测试草案 |
| UI 先行导致规则缺测 | 页面可演示但边界无法复现 | 暂停后续页面，先补领域用例和固定时钟测试 |
| 需要新依赖 | 出现大量手写系统适配或测试代码 | 说明简化内容和程度，取得用户同意后再改构建配置 |
| 范围膨胀 | 出现登录、云同步、AI、附件等需求 | 记录为后续候选，不进入当前 MVP 分支 |

产品文档互相矛盾、平台能力无法满足现有表述，或选择会改变用户数据格式时，应暂停并请求确认，不能静默选择解释。

## 9. 最小验收数据集

- 2 条带不同标签的灵感，另有 1 条编辑后的灵感。
- 1 个秋季学期和 1 个春季学期，用于复核名称、周次与寒暑假。
- 2 个每周循环普通事件，其中 1 个选择多个星期。
- 2 个同周且互相重叠的单次普通事件，用于检查提示和展示。
- 1 门第 3 至 14 周课程，并准备第 2、3、14、15 周检查边界。
- 五种事件性质各 1 个启用事件池项目，另有 1 个停用项目。
- 同一天五类时间记录共 10 小时，其中至少两条名称相同，用于复核排行榜与 14 小时“其他”。
- 1 条跨午夜记录、1 组首尾相接记录和 1 组重叠记录。
- 1 条只使用一次名称的记录，用于复核永久删除后的统计和快捷名称。
- 1 条刚删除和 1 条已超过 `30×24` 小时的灵感。
- 1 个默认提前 5 分钟的普通事件和 1 门默认提前 25 分钟的课程，并准备权限拒绝、提醒时间已过和时区变化场景。
- 1 个完整备份、1 个未知版本备份、1 个悬空引用备份和 1 个包含重叠时间记录的备份。
- 至少一个夏令时切换日，用于验证 23 或 25 小时自然日。

## 10. 暂不执行的工作

MVP 不包含登录、云服务、跨端同步、多人协作、桌面端、Markdown 富文本、附件、AI、复杂重复提醒或自定义事件性质。提醒只包含番茄钟阶段结束，以及按提前分钟数触发的课程和普通事件提醒。

这些需求可以记录为后续候选，但不得在当前执行中预建接口、模块、字段或占位页面。只有用户明确调整 MVP 范围并同步产品与数据文档后，才能修改本计划。
