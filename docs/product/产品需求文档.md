# 一站笔记产品需求文档

## 1. 文档目的

本文档定义一站笔记首个可用版本（MVP）的产品范围和验收条件，面向产品设计、后续 vibe coding 实施和功能验收。当前所有功能均为规划内容，不代表已经实现。

## 2. 产品目标

应用要解决三个连续问题：及时记下想法、安排要做的事情、复盘时间实际花在哪里。用户应能在尽量少的操作中完成记录，不需要先建立复杂项目或分类体系。

### 2.1 成功标准

- 用户进入应用后，能在 10 秒内保存一条纯文本灵感。
- 用户能分别创建普通日程和课程，并在课表式周视图或横向事件视图中看到正确结果。
- 用户不知道做什么时，能按自定义倾向从有效事件池中随机得到一个结果。
- 用户能手动录入、回溯修改或永久删除时间记录，日、周排行榜按统一口径更新。
- 所有普通事件、事件池项目和时间记录必须属于五个固定事件性质之一；课程固定属于“学习”。

## 3. 核心概念

| 概念 | 定义 |
| --- | --- |
| 灵感 | 临时想法、感悟或待实践构思，以文本卡片保存，可附简单标签。 |
| 普通日程 | 通过普通事件入口创建的计划事项，分为每周循环事件和单次事件。 |
| 课程 | 通过独立课程入口创建的特殊日程，固定属于学习，并按学期周次展开。 |
| 事件池项目 | 可被随机抽取的候选行动，启用后参与抽奖。 |
| 番茄钟 | 纯粹的专注计时辅助工具，不参与时间记录与统计。 |
| 时间记录 | 用户手动填写或日程到达结束时间后自动结算生成的实际活动记录，是统计数据的唯一来源。 |
| 事件性质 | 工作、学习、高质量娱乐、低质量娱乐、社交。 |
| 学期 | 具有标准名称、开始日期和结束日期的教学时间范围，用于计算课程周次。 |

计划日程与实际时间记录：事件在到达结束时间前仅作为计划展示，到达结束时间后由系统自动结算为实际时间记录；若与已有手动记录重叠则优先保留手动记录。

## 4. 用户主要流程

### 4.1 快速记录灵感

1. 用户打开应用，在灵感页点击右下角悬浮加号按钮进入编辑界面。
2. 输入正文，可选填一个或多个简单标签。
3. 保存后立即看到成功反馈，卡片出现在灵感列表顶部。
4. 用户之后可以查看、编辑或将该灵感移入回收站；30 天内可以恢复，期满后永久删除。

### 4.2 创建并查看日程

1. 用户在日程页选择“添加普通事件”或独立的“添加课程”入口。
2. 普通事件填写名称、事件性质、日期或星期、开始时间、结束时间和提醒；课程填写所属学期、课程名称、地点、星期、时间、上课周范围和提醒。
3. 保存后可在课表式周视图查看时间块，也可在横向事件视图查看本周尚未结束的具体事件。
4. 用户在对应配置页修改或删除日程；两种视图只负责查看和跳转，不直接编辑。

### 4.3 随机选择行动

1. 用户预先在事件池维护候选事项，并为每项选择事件性质和 `1–100` 权重。
2. 用户点击转盘中心“抽一下”。
3. 系统从所有启用项目中按权重抽取一项，转盘减速停到对应扇区，并显示名称、事件性质和权重。
4. 用户可以重新抽取、启动番茄钟进行专注或关闭结果；番茄钟仅作为专注工具，不产生时间记录。

### 4.4 番茄专注与时间记录

1. 番茄专注：用户可随时启动番茄钟辅助专注，番茄钟作为纯粹计时工具，结束后不生成时间记录，不计入统计。
2. 时间记录：用户手动填写事件名称、事件性质、开始日期时间和结束日期时间；开始时间可以是过去时间，因此支持回溯补录。
3. 记录维护：用户可编辑历史记录；确认删除后执行永久删除，不提供回收站或恢复入口。
4. 统计计算：统计页只基于当前仍存在的有效时间记录生成日、周排行榜。

## 5. 功能需求

### 5.1 快速灵感记录

#### 用途与场景

用于随手记录临时想法、感悟和待实践构思，优先降低输入阻力。

#### MVP 要求

- 灵感页提供始终可见的右下角新增加号按钮（FAB）。
- 正文为必填项，去除首尾空白后不能为空。
- 标签为可选的简短文本，同一条灵感不得保存重复标签。
- 灵感以卡片展示，默认按最后更新时间倒序排列。
- 支持新增、查看、编辑和移入回收站；删除前需要二次确认。
- 回收站中的灵感保留 30×24 小时，期间可以恢复或手动永久删除，到期后自动永久删除。
- 保存失败时保留输入内容，并给出可理解的错误提示。

#### 暂不纳入 MVP

Markdown 富文本、附件、图片、语音转写、灵感间双向链接、AI 自动整理。

### 5.2 日程视图与普通事件

#### 用途与场景

通过课表式周视图查看一周时间分布，通过纵向事件流视图快速查看接下来要发生的事件，并在同一页面切换到实际时间统计完成复盘。

#### MVP 要求

- 日程页提供“课表”、“事件流”和“时间统计”三个视图切换入口；课表与事件流共用计划日程数据，时间统计只读取手动时间记录。
- 日程页顶部时期按钮始终按设备当前日期显示状态：日期在学期内时显示标准学期名称和当前周次，日期在已配置学期之外时显示“寒假中”或“暑假中”，尚未配置任何学期时显示“未设置学期”。
- 点击顶部时期按钮直接打开学期设置；普通事件和课程保留各自管理入口，学期不再与两类单项日程并列。
- 课表视图默认显示包含今天的自然周，以周一至周日为列、一天时间为纵轴；支持切换上一周、下一周并返回本周。
- 每周循环事件按所选星期和时间，在每个适用周自动显示；单次事件只在具体日期显示。
- 普通事件块显示名称、时间和事件性质；课程块额外显示课程名称与地点。
- 课表顶部显示当前日期范围对应的学期、寒假或暑假；跨越边界时并列显示两个标签。
- 事件流采用纵向卡片列表排列展示，只显示本周尚未结束的事件；当天事件自动按上下午（以 12:00 为界）分块排布并以空白间距自然隔开，不显示显式文字标签。
- 事件流将开始时间最早且尚未开始的事件标为“下一个事件”，并使用与普通卡片可区分的特殊边框；正在进行的事件显示“进行中”，不占用“下一个事件”标记。
- 每周循环普通事件和课程在事件流中只展开本周实例，不生成下周及更远的重复实例。
- 新增普通事件与新增课程使用两个独立入口；修改、删除统一在对应配置页完成，日程视图中不提供拖拽或直接改时长。
- 开始时间必须早于结束时间；跨午夜日程在 MVP 中不允许保存。
- 时间重叠时给出提醒但允许保存，并在课表视图中并排或错开展示，不能静默覆盖。
- 日程事件到达结束时间后，系统自动将其转化为对应时间段、分类和名称的实际时间记录并纳入时间统计；离线或重启后自动补齐，若与已有手动记录重叠则静默跳过。
- 每周循环普通事件从生效日期开始渲染，默认生效日期为创建当天；MVP 不设置自动结束日期。
- 普通事件默认开启开始前 5 分钟提醒，用户可以逐项关闭提醒或修改提前分钟数。
- 提醒时间已过但事件尚未开始时，新增或修改成功后立即提醒一次；事件已经开始或结束时不补发。

#### 两种普通事件规则

| 类型 | 必填信息 | 渲染规则 |
| --- | --- | --- |
| 每周循环普通事件 | 名称、事件性质、至少一个星期、开始时间、结束时间、生效日期 | 从生效日期起，在用户选择的每个星期重复显示，直到事件被停用或删除。 |
| 单次普通事件 | 名称、事件性质、具体日期、开始时间、结束时间 | 只在指定日期显示一次。 |

单次普通事件按具体日期保存，避免切换周次后含义不清。事件名称允许自由填写，表单同时提供来自现存历史数据的去重快捷选项；选择快捷项只填充名称，不自动带入事件性质、日期或时间。

### 5.3 学期与课程

#### 用途与场景

设置教学时间范围，让课程按真实学期周次自动出现在日程中，并让用户在日程顶部识别当前学期或假期。

#### 学期设置

- 点击日程页顶部时期按钮打开学期列表，用户填写学年起始年份、季节、开始日期和结束日期。
- 学期名称由系统按“起始年份-下一年份季节学期”生成，例如学年起始年份为 2026、季节为秋季时显示 `2026-2027秋季学期`，不允许另行填写不符合规则的名称。
- 开始日期不得晚于结束日期；两个学期日期范围不得重叠。
- 学期第 1 周是包含开始日期的周一至周日，此后每个周一进入下一周；结束日期之后不再属于该学期。
- 不在学期内的日期显示为寒假或暑假：秋季学期结束到下一春季学期开始之间为寒假，春季学期结束到下一秋季学期开始之间为暑假；只配置当前一个学期时，其秋季学期前为暑假、后为寒假，其春季学期前为寒假、后为暑假。

#### 课程要求

- “添加课程”与“添加普通事件”入口分开，避免普通重复规则与课程周次规则混淆。
- 课程必填所属学期、课程名称、地点、至少一个星期、开始时间、结束时间、开始周和结束周。
- 课程事件性质固定为“学习”，表单不显示可修改的事件性质选择器。
- 开始周和结束周为正整数，开始周不得大于结束周，且不得超出所属学期实际周数。
- 查看某周时，系统先根据学期开始日期计算实际周次；只有实际周次落在闭区间（例如第 3 周至第 14 周）内，才在所选星期渲染课程。
- 课程卡片在课表和事件流中均显示课程名称、地点和起止时间；地点不得仅依赖详情页才能看到。
- 课程名称允许自由填写，并提供来自现存课程的去重快捷选项；选择后仍需用户确认地点、周次与时间。
- 课程默认开启开始前 25 分钟提醒，用户可以逐项关闭提醒或修改提前分钟数。

### 5.4 番茄钟

#### 用途与场景

纯粹的专注计时辅助工具，帮助用户保持专注节奏。番茄钟不与时间统计打通，不生成时间记录。

#### MVP 要求

- 默认专注/休息时长为 25/5 分钟；启动前可以调整本轮时长，并把最近一次设置作为下次默认值。
- 专注时长允许 1–180 分钟，休息时长允许 1–60 分钟，输入精确到分钟。
- 启动前可选择或填写当前专注事项（仅用于计时界面提示）。
- 支持开始、暂停、继续、重置和提前结束。
- 专注阶段和休息阶段结束时提供状态提示/提醒，纯粹作为辅助工具，不生成时间记录，不计入统计。
- 专注结束后由用户确认是否开始休息，休息结束后也不自动开始下一轮专注。
- 应用进入后台后，计时结果必须依据真实时间计算，不能仅依赖前台动画累加。
- 应用被系统终止、异常退出或设备重启后，下次打开时按持久化截止时间和真实经过时间恢复；若阶段已经结束，只显示已完成状态，不补发过期提醒。

### 5.5 加权转盘抽奖

#### 用途与场景

当用户没有明确行动目标时，从预先录入的事件池中随机选择一件事。

#### MVP 要求

- 事件池项目包含名称、事件性质、`1–100` 权重和启用状态，可新增、编辑、停用和删除；权重默认 `1`。
- 启用项目以彩色转盘扇区展示，扇区角度和标注占比均与该项目权重占启用项目总权重的比例一致。
- 每次仅从启用项目中按权重独立抽取一项；单项显示完整圆并直接命中，停用项不渲染也不参与抽取。
- 事件池为空时，不执行抽取，并引导用户先添加项目。
- 转盘以平滑减速动画精确停到中选扇区；结果展示项目名称、事件性质和权重，并提供“再抽一次”和“带入番茄钟”。
- 新增和编辑表单实时显示当前权重及其在启用项目总权重中的占比。
- 名称可以自由填写；新增或编辑时提供来自现存事件池项目的去重历史快捷选项，选择后不自动修改事件性质。
- 每次抽取互相独立，不承诺避免连续抽中同一项。

按时段过滤、抽取历史和冷却机制不纳入 MVP。

### 5.6 五种固定事件性质

所有普通日程、事件池项目和时间记录必须选择以下一类：

1. 工作
2. 学习
3. 高质量娱乐
4. 低质量娱乐
5. 社交

事件性质名称在 MVP 中不可新增、删除或重命名，以保证统计口径稳定。普通日程、事件池项目和时间记录必须选择其中一项，课程固定为“学习”。灵感不强制归类，因为标签已经承担轻量整理作用。

### 5.7 时间记录与排行榜统计

#### 用途与场景

手动记录实际花费时间，并按天或周通过排行榜比较五种事件性质或具体事件名称的累计时长。

#### MVP 要求

- 时间记录由用户手动录入及日程事件到达结束时间后自动结算生成（来源分别为 manual 和 schedule），番茄钟不产生时间记录。
- 手动录入表单要求用户填写事件名称、事件性质、开始日期时间和结束日期时间，各字段均可单独修改；允许开始日期时间早于当前时间，以支持任意历史记录回溯。
- 事件名称允许自由填写，并提供根据当前仍存在的历史时间记录生成的去重快捷选项；选择快捷项只填充名称，其余参数仍由用户输入。
- 同一时间段存在重叠记录时必须提示并阻止保存，避免重复统计。
- 统计页保留日、周范围切换，并提供“按事件性质”和“按事件名称”两种排行榜视图。
- 事件性质排行榜将五种事件性质按累计时长从长到短排列；事件名称排行榜将范围内名称相同的记录合并后按累计时长排列。
- 排行榜每项显示名次、名称和精确时长，不展示百分比、饼图、环形图或占比条。
- 用户修改记录后立即重算相关统计。用户确认删除后永久移除记录，删除时间不再纳入任何统计，不进入回收站且不可恢复。
- 快捷名称只从当前仍存在的记录生成；永久删除某名称的最后一条记录后，该名称不再因已删除记录出现在快捷选项中。
- 统计计算遵循[数据模型与统计口径](../reference/数据模型与统计口径.md)。

#### 排序规则

- 首要排序键为累计时长降序。
- 时长相同时，事件性质榜按固定事件性质顺序排列；事件名称榜按名称的本地化升序排列，保证同一数据集结果稳定。
- 空数据时显示“该时段还没有时间记录”和手动录入入口，不生成无意义的空名次。
- 排行榜不能只靠颜色区分事件性质，必须显示文字名称与精确时长。

## 6. 页面范围

MVP 包含以下四大主选项卡与二级配置界面：

- **日程**：默认启动首页，整合课表式周视图、纵向事件流视图、时间统计与记录明细，提供普通事件、课程与学期配置入口。
- **灵感**：灵感卡片列表、右下角新增入口、全量编辑界面与顶部回收站入口。
- **工具箱**：App 桌面网格门户（App Grid Launcher），以方形图标卡片聚合展示番茄钟与幸运大转盘入口，支持进入独立专属工具页面（独立番茄专注页面、独立幸运大转盘页面），并保留跨工具一键带入番茄钟的快捷联动能力。
- **设置**：外观主题切换（跟随系统/浅色/深色）、系统提醒权限管理、数据备份与恢复。
- 普通事件配置：循环事件和单次事件列表、编辑表单。
- 课程配置：课程列表、所属学期、地点和上课周编辑表单。
- 学期配置：学期列表、起止日期与编辑表单。
- 灵感回收站：恢复未到期灵感或提前永久删除。

详细结构见[页面与交互说明](页面与交互说明.md)。

## 7. 数据与隐私原则

- MVP 按本地优先设计，个人灵感、日程和时间记录默认只存储在设备上，依赖 Android 应用沙箱和设备文件级加密，不增加应用锁或数据库额外加密。
- 不使用云同步或自动备份。用户可以通过系统文件选择器手动导出、恢复数据备份文件；导出前必须提示文件包含个人数据。
- 备份包含全部业务数据、灵感回收站和设置，但不包含进行中的番茄钟。导入前完整校验，确认后事务性整体替换现有数据；存在活动计时时必须先结束计时。
- 不请求与核心功能无关的系统权限。
- 番茄钟阶段结束和日程准点提醒需要通知权限；日程提醒还需要 Android 的“闹钟和提醒”特殊权限。只在启用相关提醒时请求，并说明用途。
- 用户拒绝通知或“闹钟和提醒”权限时仍可保存日程，但界面必须明确标记提醒未启用并提供系统设置入口，不能静默声称提醒成功。
- 灵感删除后进入 30 天回收站；普通事件、课程、学期、事件池项目和时间记录确认后永久删除，不提供恢复。

## 8. 非功能要求

- 首屏核心记录入口应快速可用，不因排行榜或历史统计加载而被阻塞。
- 关键操作需要明确的成功、空状态和失败反馈。
- 使用简洁蓝色 Material 3 视觉风格，支持跟随系统、浅色或深色主题模式自由切换，并在 Android 12+ 设备上支持壁纸动态取色；MVP 只适配手机竖屏，不单独支持横屏、平板或折叠屏布局。
- 在常见 Android 手机竖屏尺寸上，课表视图和事件流允许必要的横向或纵向滚动，但课程名称、地点等关键信息不能被不可恢复地截断。
- 日程和时间记录输入精确到分钟，统计显示小时和分钟。
- 时间、日期和周边界统一使用设备当前时区；历史记录随当前时区重新归日，夏令时切换日按该时区自然日的实际长度计算。
- 核心数据写入应具备事务性，避免只保存事件或课程的一部分字段。
- 所有面向用户的文案使用中文，日期、时长格式保持一致。

## 9. MVP 总体验收标准

满足以下条件才视为首版产品闭环完成：

1. 新用户无需注册即可创建、编辑、移入回收站和恢复灵感。
2. 两类普通事件均可配置，并在正确的周和时间位置显示。
3. 学期名称与假期标签正确，课程只在所属学期的上课周范围内显示，且卡片包含课程名称和地点。
4. 课表和事件流读取相同数据；事件流隐藏已结束事件、突出下一个事件，周常事件只展开本周。
5. 重叠日程可见且有提示，非法时间范围不可保存。
6. 事件池能够维护权重，空池有引导，转盘扇区比例准确且只从启用项目中按权重抽取，动画落点与结果一致。
7. 番茄钟按 25/5 分钟默认值及允许范围运行，能够在应用终止或重启后按真实时间恢复，不生成时间记录，不参与时间统计。
8. 时间记录可手动填写全部业务参数并回溯历史；相邻记录可保存，重叠记录不可保存。
9. 删除时间记录后无法恢复，相关日、周排行榜和快捷名称立即排除已删除数据。
10. 两种排行榜的累计时长与时间记录明细人工核算一致，不出现百分比。
11. 自由填写的事件名称可保存，历史快捷选项只填名称且不限制继续输入新名称。
12. 课程和普通事件使用正确的默认提前量；逐项修改、权限拒绝、错过提醒时间和导入后重建提醒均有明确结果。
13. 灵感可以在 30 天内从回收站恢复，其他实体永久删除；明文 JSON 可以完整导出并在校验后整体替换导入。
14. 应用重启后已保存数据仍然存在，进行中的番茄钟按真实经过时间恢复。
15. 空数据、错误输入、删除确认和保存失败都有清晰反馈。
16. README、产品文档和实际功能保持一致。

## 10. 明确不在 MVP 范围

- iOS、Web、桌面端和多人协作。
- 账号登录、云同步、跨设备同步和在线社区。
- 接入系统日历或第三方任务平台。
- AI 总结、自动分类、智能排期和自动生成建议。
- 富文本笔记、文件附件、语音识别和 OCR。
- 复杂重复规则、跨午夜日程、月视图和年视图。
- 游戏化积分、与他人比较的社交排行榜和公开分享；本需求中的排行榜仅比较用户自己的时间投入。

## 11. 已确认 MVP 决策

- 正式应用名称为“一站笔记”，使用 Kotlin 与 Jetpack Compose 原生开发，最低支持 Android 12（API 31）。
- 番茄钟默认专注/休息时长为 25/5 分钟，可按规定范围调整；阶段之间由用户确认开始，终止或重启后按真实时间恢复。
- 提供手动明文 JSON 导入、导出，不提供云同步或自动备份；导入采用完整校验后整体替换。
- 课程默认提前 25 分钟、普通事件默认提前 5 分钟提醒，均可逐项关闭或修改；准点提醒所需权限被拒绝时保留日程并明确标记未提醒。
- 历史数据按设备当前时区重新归日，夏令时切换日使用实际自然日长度。
- 灵感进入 30 天回收站，其他业务实体确认后永久删除。
- 技术栈、依赖、屏幕范围和交付方式见[采用原生 Android 技术栈](../adr/0001-采用原生Android技术栈.md)。
