# NoteApp All-in-One 产品需求文档

## 1. 文档目的

本文档定义 NoteApp All-in-One 首个可用版本（MVP）的产品范围和验收条件，面向产品设计、后续 vibe coding 实施和功能验收。当前所有功能均为规划内容，不代表已经实现。

## 2. 产品目标

应用要解决三个连续问题：及时记下想法、安排要做的事情、复盘时间实际花在哪里。用户应能在尽量少的操作中完成记录，不需要先建立复杂项目或分类体系。

### 2.1 成功标准

- 用户进入应用后，能在 10 秒内保存一条纯文本灵感。
- 用户能在独立配置页面创建任务，并在周视图中看到正确的日期和时间位置。
- 用户不知道做什么时，能从有效事件池中公平随机得到一个结果。
- 用户完成番茄钟或手动打卡后，日、周统计能按统一口径更新。
- 所有任务和事件必须属于四个固定分类之一；“其他”只由系统计算。

## 3. 核心概念

| 概念 | 定义 |
| --- | --- |
| 灵感 | 临时想法、感悟或待实践构思，以文本卡片保存，可附简单标签。 |
| 日程任务 | 显示在周时间表中的计划事项，分为每周循环任务和单周一次性任务。 |
| 事件池项目 | 可被随机抽取的候选行动，启用后参与抽奖。 |
| 番茄钟 | 用于执行某件事的专注计时；完成后可生成实际时间记录。 |
| 时间记录 | 用户实际花费时间的打卡记录，是统计数据的唯一来源。 |
| 固定分类 | 工作学习、高质量娱乐、低质量娱乐、社交。 |
| 其他 | 一天总分钟数减去四类有效时间记录后的剩余时间，不可手动选择。 |

计划日程与实际时间记录必须分开：任务出现在课表中不代表用户已经执行，也不能直接进入时间统计。

## 4. 用户主要流程

### 4.1 快速记录灵感

1. 用户打开应用，在首页直接点击快速输入区。
2. 输入正文，可选填一个或多个简单标签。
3. 保存后立即看到成功反馈，卡片出现在灵感列表顶部。
4. 用户之后可以查看、编辑或删除该灵感。

### 4.2 创建并查看日程

1. 用户进入任务配置页，选择“每周循环”或“单次任务”。
2. 填写标题、固定分类、日期或星期、开始时间和结束时间。
3. 保存后返回周视图，任务按对应时间段显示。
4. 用户在任务配置页修改或删除任务；周视图只负责查看和跳转，不直接编辑。

### 4.3 随机选择行动

1. 用户预先在事件池维护候选事项，并为每项选择固定分类。
2. 用户点击“帮我选一个”。
3. 系统从所有启用项目中等概率抽取一项，并显示名称和分类。
4. 用户可以重新抽取、开始番茄钟或关闭结果；开始番茄钟不等于已完成打卡。

### 4.4 执行与打卡

1. 用户选择任务或事件，或者临时输入一件事。
2. 选择固定分类，并启动番茄钟；默认专注和休息时长在编码前确认。
3. 专注阶段结束后，用户确认保存，本次实际区间生成时间记录。
4. 用户也可以手动补录开始时间、结束时间、事项和分类。
5. 统计页基于有效时间记录重新计算日、周结果。

## 5. 功能需求

### 5.1 快速灵感记录

#### 用途与场景

用于随手记录临时想法、感悟和待实践构思，优先降低输入阻力。

#### MVP 要求

- 首页提供始终可见的快速记录入口。
- 正文为必填项，去除首尾空白后不能为空。
- 标签为可选的简短文本，同一条灵感不得保存重复标签。
- 灵感以卡片展示，默认按最后更新时间倒序排列。
- 支持新增、查看、编辑和删除；删除前需要二次确认。
- 保存失败时保留输入内容，并给出可理解的错误提示。

#### 暂不纳入 MVP

Markdown 富文本、附件、图片、语音转写、灵感间双向链接、AI 自动整理。

### 5.2 课表式周时间视图

#### 用途与场景

以周一至周日为列、一天时间为纵轴，像大学课表一样集中查看一周计划。

#### MVP 要求

- 默认显示包含今天的自然周，周一为一周开始。
- 支持切换上一周、下一周，并一键返回本周。
- 每周循环任务按所选星期和时间，在每个适用周自动显示。
- 单次任务只在其具体日期所属的周显示。
- 任务卡片显示标题、时间和分类颜色；点击可查看详情并跳转配置页。
- 新增、修改、删除任务统一在独立任务配置页完成，周视图中不提供拖拽或直接改时长。
- 开始时间必须早于结束时间；跨午夜任务在 MVP 中不允许保存。
- 时间重叠时给出提醒但允许保存，并在周视图中并排或错开展示，不能静默覆盖。
- 周视图展示的是计划，不自动生成实际时间记录。
- 每周循环任务从生效日期开始渲染，默认生效日期为创建当天；MVP 不设置自动结束日期。

#### 两种任务规则

| 类型 | 必填信息 | 渲染规则 |
| --- | --- | --- |
| 每周循环任务 | 标题、分类、至少一个星期、开始时间、结束时间、生效日期 | 从生效日期起，在用户选择的每个星期重复显示，直到任务被停用或删除。 |
| 单周一次性任务 | 标题、分类、具体日期、开始时间、结束时间 | 只在指定日期显示一次。 |

“单周一次性任务”按具体日期保存，避免切换周次后含义不清。

### 5.3 番茄钟

#### 用途与场景

帮助用户专注执行事项，并把实际完成的专注时间转化为可复盘数据。

#### MVP 要求

- 启动前显示事项名称、固定分类和本轮专注时长。
- 支持开始、暂停、继续和提前结束。
- 专注结束时提示用户保存或放弃本次记录，不能在未确认时直接计入统计。
- 保存的时间记录使用实际专注区间；休息时间不进入四类统计。
- 应用进入后台后，计时结果必须依据真实时间计算，不能仅依赖前台动画累加。
- 计时中断、系统重启或应用异常退出后的恢复策略需在编码前确认并测试。

### 5.4 随机抽奖

#### 用途与场景

当用户没有明确行动目标时，从预先录入的事件池中随机选择一件事。

#### MVP 要求

- 事件池项目包含名称、固定分类和启用状态，可新增、编辑、停用和删除。
- 每次仅从启用项目中等概率抽取一项。
- 事件池为空时，不执行抽取，并引导用户先添加项目。
- 抽取结果展示项目名称和分类，并提供“再抽一次”和“开始番茄钟”。
- 每次抽取互相独立，不承诺避免连续抽中同一项。

加权抽取、按时段过滤、抽取历史和冷却机制不纳入 MVP。

### 5.5 四大固定分类

所有日程任务、事件池项目和时间记录必须选择以下一类：

1. 工作学习
2. 高质量娱乐
3. 低质量娱乐
4. 社交

分类名称在 MVP 中不可新增、删除或重命名，以保证统计口径稳定。灵感不强制归类，因为标签已经承担轻量整理作用。

“其他”是统计结果，不是第五个可选分类。任何创建或编辑表单都不得把“其他”放入分类选择器。

### 5.6 时间统计与打卡

#### 用途与场景

记录实际花费时间，并按天或周复盘四类活动的时长和占比。

#### MVP 要求

- 支持由番茄钟确认生成记录，也支持手动补录。
- 手动记录包含事项名称、固定分类、开始时间和结束时间。
- 同一时间段存在重叠记录时必须提示并阻止保存，避免重复统计。
- 日统计展示四类时长、各类占已记录时间的比例，以及“其他”时长。
- 周统计按周一至周日汇总四类时长，并展示分类总时长和比例。
- 用户修改或删除时间记录后，相关统计立即按新数据重算。
- 没有任何四类记录时，分类占比统一显示为 0%，不得出现除零错误。
- 统计计算遵循[数据模型与统计口径](../reference/数据模型与统计口径.md)。

#### 建议可视化

- 日统计：四类时间的环形图或横向占比条，同时显示精确时长；“其他”单独展示。
- 周统计：按日期堆叠柱状图，并列出四类一周总时长。

图表不能取代文字数值，颜色需要与周视图的分类颜色保持一致，并满足基本对比度要求。

## 6. 页面范围

MVP 包含以下页面或界面：

- 今日：首页、快速灵感入口、当前番茄钟入口。
- 周视图：课表式计划展示。
- 灵感：灵感列表和编辑界面。
- 统计：日统计、周统计和时间记录明细。
- 任务配置：循环任务和单次任务列表、编辑表单。
- 事件池与抽奖：候选项目管理、抽取结果。
- 番茄钟：计时与结束确认。
- 设置：后续只放确有实现的本地配置，不预设复杂账号功能。

详细结构见[页面与交互说明](页面与交互说明.md)。

## 7. 数据与隐私原则

- MVP 按本地优先设计，个人灵感、日程和时间记录默认只存储在设备上。
- 文档不承诺云同步或自动备份；卸载应用可能导致本地数据丢失，最终行为需在实现前确认并明确提示。
- 不请求与核心功能无关的系统权限。
- 通知、闹钟和后台计时如需系统权限，必须在实际需要时请求，并说明用途。
- 删除数据应有确认步骤；是否提供回收站属于待确认范围。

## 8. 非功能要求

- 首屏核心记录入口应快速可用，不因图表或历史统计加载而被阻塞。
- 关键操作需要明确的成功、空状态和失败反馈。
- 在常见 Android 手机尺寸上，周视图允许横向或纵向滚动，但文字不能被不可恢复地截断。
- 时间、日期和周边界统一使用设备当前时区；时区变化后的历史记录展示策略见统计口径文档。
- 核心数据写入应具备事务性，避免只保存任务的一部分字段。
- 所有面向用户的文案使用中文，日期、时长格式保持一致。

## 9. MVP 总体验收标准

满足以下条件才视为首版产品闭环完成：

1. 新用户无需注册即可创建、编辑和删除灵感。
2. 两类日程任务均可配置，并在正确的周和时间位置显示。
3. 重叠日程可见且有提示，非法时间范围不可保存。
4. 事件池能够维护，空池有引导，有效项目可等概率抽取。
5. 番茄钟完成后须经确认才生成时间记录，休息时间不计入分类统计。
6. 手动打卡与番茄钟记录使用同一统计口径，重叠记录不可重复保存。
7. 日、周统计结果与时间记录明细人工核算一致，“其他”不会成为可选分类。
8. 应用重启后已保存数据仍然存在，进行中的番茄钟按最终确定的恢复策略工作。
9. 空数据、错误输入、删除确认和保存失败都有清晰反馈。
10. README、产品文档和实际功能保持一致。

## 10. 明确不在 MVP 范围

- iOS、Web、桌面端和多人协作。
- 账号登录、云同步、跨设备同步和在线社区。
- 接入系统日历或第三方任务平台。
- AI 总结、自动分类、智能排期和自动生成建议。
- 富文本笔记、文件附件、语音识别和 OCR。
- 复杂重复规则、跨午夜任务、月视图和年视图。
- 游戏化积分、社交排行榜和公开分享。

## 11. 待确认决策

以下事项会影响实现，不应由编码过程默默决定：

- 正式应用名称是否为 “NoteApp All-in-One”。
- 原生 Android 还是跨平台技术栈，以及最低支持的 Android 版本。
- 番茄钟默认专注/休息时长是否为 25/5 分钟，用户是否可调整。
- 进行中的番茄钟在应用被系统终止或设备重启后的恢复规则。
- 是否需要本地导出、导入或自动备份，以及数据格式。
- 是否需要任务开始提醒；若需要，提前多久、如何处理通知权限。
- “一天总时间”是否固定为自然日 24 小时；夏令时地区是否按实际自然日长度处理。
- 删除灵感、任务和时间记录是立即永久删除，还是进入回收站。
