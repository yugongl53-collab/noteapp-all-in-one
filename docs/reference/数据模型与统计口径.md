# 数据模型与统计口径草案

## 1. 文档目的

本文档定义 MVP 需要表达的数据实体、字段约束、提醒与备份契约和时间统计口径，减少后续实现中对同一概念的不同解释。M1 已将第 2 至 8 节涉及的结构化业务数据映射到 Room，并将 `AppSettings` 和活动 `PomodoroSession` 映射到 DataStore；M4 已实现第 5.3 节的日程提醒，M6 已实现第 8 至 13 节的时间记录与统计，M7 已实现第 14 节的 JSON 备份与导入。

### 1.1 M1 存储实现边界

- Room 数据库入口为 `NoteDatabase`，数据库版本为 `2`；六类实体分别通过对应 DAO 的 `save` 入口执行规范化和事务式校验。版本 `1` 升级时通过 `MIGRATION_1_2` 为既有事件池项目补入默认权重 `1`。
- Room 绝对时间保存为 Unix Epoch 毫秒，当地日期保存为 ISO `YYYY-MM-DD`，当地时刻保存为当天分钟数，事件性质和枚举保存稳定标识。
- 当前 Schema 快照位于 `app/schemas/com.yuncun.noteapp.data.local.NoteDatabase/2.json`。数据库版本升级必须提供显式迁移，不能使用破坏性回退。
- 学年与季节由唯一索引防止同名学期；课程通过受限外键引用学期；时间记录对普通日程和事件池的可选引用在来源删除后置空，不删除历史记录。
- `AppPreferencesRepository` 原子保存设置或完整番茄钟会话。通知权限和“闹钟和提醒”权限没有对应 DataStore 键，调用方必须读取 Android 当前系统状态。

验证存储实现时先运行 `./gradlew testDebugUnitTest`，再运行 `./gradlew assembleDebugAndroidTest`；连接 API 31 或更高版本设备后运行 `./gradlew connectedDebugAndroidTest`，确认约束、重启读取和 DataStore 重建用例通过。

## 2. 固定事件性质

内部应使用稳定标识，界面显示中文名称，避免未来文案调整破坏历史数据。

| 稳定标识 | 显示名称 | 可由用户选择 |
| --- | --- | --- |
| `work` | 工作 | 是 |
| `study` | 学习 | 是；课程固定使用该值。 |
| `high_quality_entertainment` | 高质量娱乐 | 是 |
| `low_quality_entertainment` | 低质量娱乐 | 是 |
| `social` | 社交 | 是 |

普通日程、事件池项目和时间记录只允许保存上述五个标识。课程只能保存 `study`。

## 3. 核心实体

### 3.1 灵感 `Idea`

| 字段 | 用途 | 必填 | 约束 |
| --- | --- | --- | --- |
| `id` | 本地唯一标识 | 是 | 创建后不可变。 |
| `content` | 灵感正文 | 是 | 去除首尾空白后非空。 |
| `tags` | 简单标签集合 | 否 | 同一灵感内去重。 |
| `createdAt` | 创建时间 | 是 | 绝对时间戳。 |
| `updatedAt` | 最后更新时间 | 是 | 不早于 `createdAt`。 |
| `deletedAt` | 移入回收站时间 | 否 | 非空表示已删除；到达该绝对时间点后 30×24 小时永久清理。 |

常规列表只查询 `deletedAt = null` 的灵感。恢复时清空 `deletedAt`，不修改原有 `createdAt` 和 `updatedAt`；手动永久删除或保留期到期后硬删除记录。

### 3.2 普通日程 `ScheduleTask`

| 字段 | 用途 | 必填 | 约束 |
| --- | --- | --- | --- |
| `id` | 本地唯一标识 | 是 | 创建后不可变。 |
| `title` | 事件名称 | 是 | 去除首尾空白后非空，允许自由填写。 |
| `category` | 事件性质 | 是 | 只能是五个可选事件性质之一。 |
| `type` | 事件类型 | 是 | `weekly` 或 `one_off`。 |
| `weekdays` | 循环星期集合 | 条件必填 | `weekly` 至少选择一天，`one_off` 不使用。 |
| `effectiveFrom` | 循环生效日期 | 条件必填 | `weekly` 必填，默认创建当天；`one_off` 不使用。 |
| `date` | 具体日期 | 条件必填 | `one_off` 必填，`weekly` 不使用。 |
| `startTime` | 当地开始时刻 | 是 | 必须早于 `endTime`。 |
| `endTime` | 当地结束时刻 | 是 | MVP 不允许跨午夜。 |
| `isEnabled` | 是否参与日程展开 | 是 | 默认启用；停用后保留配置但不渲染。 |
| `reminderEnabled` | 是否启用提醒 | 是 | 默认 `true`。 |
| `reminderAdvanceMinutes` | 提前分钟数 | 条件必填 | 启用提醒时为非负整数，普通事件默认 `5`。 |
| `createdAt` | 创建时间 | 是 | 绝对时间戳。 |
| `updatedAt` | 最后更新时间 | 是 | 绝对时间戳。 |

所有生效的普通日程都应该被渲染到时间表。周视图按查看周的当地日期展开循环规则，不需要为每周预先复制一批记录。

### 3.3 学期 `AcademicTerm`

| 字段 | 用途 | 必填 | 约束 |
| --- | --- | --- | --- |
| `id` | 本地唯一标识 | 是 | 创建后不可变。 |
| `academicYearStart` | 学年起始年份 | 是 | 四位整数；结束年份固定为该值加一。 |
| `season` | 学期季节 | 是 | `fall`（秋季）或 `spring`（春季）。 |
| `startDate` | 学期开始日期 | 是 | 当地日期，不晚于 `endDate`。 |
| `endDate` | 学期结束日期 | 是 | 当地日期；与其他学期范围不得重叠。 |
| `createdAt` | 创建时间 | 是 | 绝对时间戳。 |
| `updatedAt` | 最后更新时间 | 是 | 绝对时间戳。 |

显示名称不重复持久化，由 `academicYearStart`、下一年份和 `season` 派生，例如 `academicYearStart = 2026`、`season = fall` 显示为 `2026-2027秋季学期`。这样可以避免名称与时间字段互相矛盾。

### 3.4 课程 `CourseSchedule`

| 字段 | 用途 | 必填 | 约束 |
| --- | --- | --- | --- |
| `id` | 本地唯一标识 | 是 | 创建后不可变。 |
| `termId` | 所属学期 | 是 | 必须引用现存 `AcademicTerm`。 |
| `courseName` | 课程名称 | 是 | 去除首尾空白后非空，允许自由填写。 |
| `location` | 上课地点 | 是 | 去除首尾空白后非空。 |
| `category` | 事件性质 | 是 | 固定为 `study`，用户不可修改。 |
| `weekdays` | 上课星期集合 | 是 | 至少选择一天。 |
| `startTime` | 当地开始时刻 | 是 | 必须早于 `endTime`。 |
| `endTime` | 当地结束时刻 | 是 | MVP 不允许跨午夜。 |
| `startWeek` | 开始周 | 是 | 正整数，不大于 `endWeek`。 |
| `endWeek` | 结束周 | 是 | 不得大于所属学期实际周数。 |
| `reminderEnabled` | 是否启用提醒 | 是 | 默认 `true`。 |
| `reminderAdvanceMinutes` | 提前分钟数 | 条件必填 | 启用提醒时为非负整数，课程默认 `25`。 |
| `createdAt` | 创建时间 | 是 | 绝对时间戳。 |

课程与普通日程分开建模，因为课程的生命周期由学期和周次共同约束。课程只按规则即时展开，不为每次上课预存独立记录。

| 字段 | 用途 | 必填 | 约束 |

| `title` | 候选行动名称 | 是 | 去除首尾空白后非空。 |
| `category` | 事件性质 | 是 | 只能是五个可选事件性质之一。 |
| `isEnabled` | 是否参与抽取 | 是 | 默认启用。 |
| `weight` | 加权抽取比重 | 是 | `1–100` 的整数，默认 `1`。 |
| `createdAt` | 创建时间 | 是 | 绝对时间戳。 |
| `updatedAt` | 最后更新时间 | 是 | 绝对时间戳。 |

### 3.6 时间记录 `TimeRecord`

| 字段 | 用途 | 必填 | 约束 |
| --- | --- | --- | --- |
| `id` | 本地唯一标识 | 是 | 创建后不可变。 |
| `title` | 实际活动名称 | 是 | 去除首尾空白后非空。 |
| `category` | 事件性质 | 是 | 只能是五个可选事件性质之一。 |
| `startAt` | 实际开始时间 | 是 | 绝对时间戳；用户输入精确到分钟，秒和更小单位规范为零。 |
| `endAt` | 实际结束时间 | 是 | 必须晚于 `startAt`；用户输入精确到分钟。 |
| `source` | 记录来源 | 是 | `manual`（手动录入）或 `schedule`（日程自动结算）。 |
| `relatedTaskId` | 关联普通日程 | 否 | 普通日程自动结算时记录关联标识；来源删除后置空，不删除历史记录。 |
| `relatedPoolItemId` | 关联事件池项目 | 否 | 项目删除后不应导致记录丢失。 |
| `createdAt` | 创建时间 | 是 | 绝对时间戳。 |
| `updatedAt` | 最后更新时间 | 是 | 绝对时间戳。 |

用户在新建或编辑表单中手动输入 `title`、`category`、`startAt` 和 `endAt`，来源为 `manual`；已启用的普通日程与课程在到达结束时间后由系统自动结算生成，来源为 `schedule`。开始时间不受当前时间下限约束，因此可回溯任意历史时间；统计以记录自身保存的名称、事件性质和时间为准，避免关联对象修改后篡改历史统计。

### 3.7 番茄钟会话 `PomodoroSession`

| 字段 | 用途 | 必填 | 约束 |
| --- | --- | --- | --- |
| `id` | 会话唯一标识 | 是 | 创建后不可变。 |
| `title` | 本轮事项 | 否 | 用于界面提示。 |
| `phase` | 当前阶段 | 是 | `focus` 或 `rest`。 |
| `plannedFocusMinutes` | 计划专注分钟数 | 是 | `1...180`，默认或最近一次设置为 `25`。 |
| `plannedRestMinutes` | 计划休息分钟数 | 是 | `1...60`，默认或最近一次设置为 `5`。 |
| `startedAt` | 实际启动时间 | 是 | 绝对时间戳。 |
| `targetEndAt` | 运行阶段截止时间 | 条件必填 | `running` 时必填；用于后台、进程终止和设备重启后的真实时间恢复。 |
| `remainingSeconds` | 暂停时剩余秒数 | 条件必填 | `paused` 时必填且不小于零，继续时据此生成新的 `targetEndAt`。 |
| `state` | 会话状态 | 是 | `running`、`paused` 或 `completed`。 |
| `updatedAt` | 状态更新时间 | 是 | 绝对时间戳。 |

番茄钟会话仅表示当前运行状态，纯粹作为专注工具，不生成 `TimeRecord`，不参与任何时间统计。应用重新打开时，`running` 状态以当前绝对时间和 `targetEndAt` 计算结果；已过期则转为 `completed`，显示完成状态但不补发过期通知。专注和休息阶段结束后都等待用户操作，不自动切换或循环。

Android 阶段结束通知只依赖通知权限，使用普通可唤醒系统闹钟；“闹钟和提醒”特殊权限只属于课程和普通事件的准点提醒前置条件。系统可能因省电策略延迟普通闹钟，但界面剩余时间与恢复状态始终以 `targetEndAt` 为准。

### 3.8 应用设置 `AppSettings`

| 字段 | 用途 | 必填 | 约束 |
| --- | --- | --- | --- |
| `lastFocusMinutes` | 下次默认专注时长 | 是 | `1...180`，初始值 `25`。 |
| `lastRestMinutes` | 下次默认休息时长 | 是 | `1...60`，初始值 `5`。 |
| `themeMode` | 外观主题模式偏好 | 是 | `system`（跟随系统，默认）、`light`（浅色模式）或 `dark`（深色模式）。 |

通知权限和“闹钟和提醒”权限以 Android 系统状态为准，不能把 DataStore 中的布尔值当作授权事实。

## 4. 学期、假期与周次

### 4.1 学期名称

- `fall` 显示“秋季学期”，`spring` 显示“春季学期”。
- 标准名称格式为 `{academicYearStart}-{academicYearStart + 1}{季节}学期`。
- 同一学年与季节只允许存在一个学期，避免出现两个同名范围。

### 4.2 学期周次

对学期开始日期 `startDate` 和目标日期 `date`，先分别取得其所在自然周的周一 `weekStart(...)`：

`termWeek(date) = floor((weekStart(date) - weekStart(startDate)) / 7 天) + 1`

仅当 `date` 落在 `startDate...endDate` 闭区间内时周次有效。即使开始日期不是周一，包含开始日期的自然周仍为第 1 周；结束日期所在周的学期部分仍使用该周周次。

学期实际周数等于 `termWeek(endDate)`。课程的 `startWeek...endWeek` 必须落在 `1...termWeek(endDate)` 内。

### 4.3 假期标签

- 日期落在任一学期范围内时，显示该学期标准名称。
- 秋季学期结束至下一春季学期开始之间显示“寒假”。
- 春季学期结束至下一秋季学期开始之间显示“暑假”。
- 仅存在一个当前学期时：秋季学期之前显示“暑假”、之后显示“寒假”；春季学期之前显示“寒假”、之后显示“暑假”。
- 一周跨越学期与假期边界时，按日期先后并列计算涉及的标签（`AcademicCalendarRules.labelsForWeek`），日程主界面由顶部常驻时期状态栏统一样式展示。

## 5. 日程视图展开规则

### 5.1 课表视图

1. 以设备当前时区确定目标自然周，周一 00:00 为开始。
2. `weekly` 普通事件根据 `weekdays` 匹配目标周中的当地日期，并且只显示在 `effectiveFrom` 当天及之后。
3. `one_off` 普通事件根据 `date` 是否落在目标周内判断是否展示。
4. 课程先按 `termId` 找到学期，再计算目标日期的实际周次；日期属于学期、周次落在 `startWeek...endWeek` 闭区间且星期匹配时才渲染。
5. 只渲染启用普通事件和有效课程；计划时间不等于实际执行时间。
6. 重叠事件都保留，界面负责并排或错开展示。

### 5.2 横向事件视图

1. 查询范围固定为包含当前时刻的自然周。
2. 将有效的每周循环普通事件和课程只展开为本周具体实例，并合并本周单次普通事件。
3. 过滤 `endAt <= now` 的已结束实例，保留 `startAt <= now < endAt` 的进行中实例和 `startAt > now` 的未来实例。
4. 按 `startAt`、`endAt`、稳定标识依次升序排列，保证同一数据集顺序稳定。
5. 所有进行中实例标记“进行中”；未来实例中最小 `startAt` 对应的全部并列实例标记“下一个事件”。

### 5.3 日程提醒

1. 对每个未来日程实例计算 `remindAt = startAt - reminderAdvanceMinutes`；只有 `reminderEnabled = true` 才参与调度。
2. 普通事件默认提前 5 分钟，课程默认提前 25 分钟，用户可以逐项关闭或修改提前分钟数。
3. Android 通知权限或“闹钟和提醒”特殊权限未授予时，不调度准点提醒，但保留业务配置并明确返回“提醒未生效”状态。
4. 新增或修改后若 `remindAt <= now < startAt`，立即提醒一次；若 `now >= startAt`，本次实例不补发。
5. 日程修改、停用、删除、学期修改、时区变化或整体导入后，必须先取消受影响的旧提醒，再只为仍有效的未来实例调度新提醒。
6. 重复日程不预先生成无限提醒；每次只调度可确定的近期实例，并在触发、开机、应用启动或数据变化后补充后续实例。

当前实现将“近期实例”具体化为每条普通事件或课程规则的下一次有效实例。系统侧注册表只保存实例标识与已送达去重状态，不保存权限事实，也不进入 JSON 业务备份。开机、系统时间、时区或应用版本变化会触发全量重建；每次重建都重新读取当前 `ZoneId` 和 Android 权限。

### 5.4 日程自动结算与防重

1. **自动结算触发**：当时间到达已启用的日程事件（课程或普通事件）结束时刻后，系统将其自动转化为一条对应时间段、性质和名称的 `TimeRecord`（`source = "schedule"`）。
2. **幂等与防重机制**：采用 `source:sourceId:startAt:endAt` 构建唯一实例标识，并生成确定性 UUID 作为记录主键；已结算实例键保存在 `SettlementRegistry` 中，确保无论多次同步、时钟跳变还是应用重启，每个日程实例仅结算一次。
3. **离线与重启补全**：在应用冷启动、前台唤醒、进入统计页或收到系统时间/时区广播时，自动扫描并补齐所有在关机或后台期间已到达结束时间的日程记录。
4. **重叠与冲突策略**：自动结算时若检测到目标时间段已存在重叠的手动或既有记录，静默跳过该实例生成并记录已结算状态，保证用户手动录入的时间记录绝对优先，数据库半开区间无冲突。
5. **定时调度**：每次同步计算未来最早结束的日程实例结束时间，并通过系统 AlarmManager 注册唤醒闹钟，实现准点自动结算。

## 6. 历史名称快捷选项

- 普通事件、课程、事件池项目和时间记录分别从各自当前仍存在的数据中读取名称，不跨实体类型合并。
- 候选名称先去除首尾空白，再按完整字符串去重；候选按对应记录的最新 `updatedAt` 降序排列。
- 选择候选只向名称字段写值，不携带事件性质、日期、时间、地点或周次。
- 候选不是独立持久化的历史表。删除某名称的最后一个来源后，该名称立即消失，确保永久删除不会留下隐藏建议数据。

## 7. 抽奖规则

设启用事件池集合为 `E`，项目 `i` 的权重为 `wᵢ`：

- 当 `E` 为空时，返回“没有可抽取项目”的业务状态。
- 当 `E` 非空时，项目 `i` 的抽中概率和转盘扇区占比均为 `wᵢ / Σw`，扇区角度为 `360° × wᵢ / Σw`。
- 加权随机源在 `[0, Σw)` 中生成整数，通过累加权重区间选择项目；测试可注入固定随机源。
- 单次结果不修改下一次抽取的概率。
- 停用或已删除项目不进入候选集合。
- 单个启用项目占完整 `360°` 并必然命中；转盘最终旋转角必须使算法中选扇区中心与正上方指针对齐。

测试随机功能时不能要求短样本严格符合概率；应使用固定随机单位验证普通、等权、单项、极端权重、停用过滤和越界输入，并独立验证扇区比例与最终落点。

## 8. 时间记录有效性

- `endAt` 必须晚于 `startAt`。
- 一条记录可以跨日期，但统计时必须按当地自然日边界切分。
- 任意两条有效时间记录不能覆盖同一个实际时间片段；相邻记录首尾相接不算重叠。
- 时间记录由用户手动录入全部业务参数；允许录入过去的起止时间，但仍必须提供真实有效的时间范围。
- 修改记录时，应排除当前记录自身后再检查重叠。
- 删除时间记录时从应用数据中硬删除，不保留软删除副本；删除完成后该记录不得参与查询、排行榜或名称快捷选项，也不提供恢复标识。

## 9. 日统计口径

对目标当地自然日 `D`：

1. 将与 `D` 相交的每条时间记录裁剪到当天边界。
2. 按事件性质累加裁剪后的分钟数，得到五类时长 `C1...C5`。
3. 已记录总时长 `R = C1 + C2 + C3 + C4 + C5`。
4. 按事件名称累加裁剪后的分钟数；名称分组使用去除首尾空白后的完整字符串，不执行模糊匹配或自动同义词合并。

“当天总分钟数”取设备当前时区中目标当地自然日的实际长度。普通日期为 1440 分钟，夏令时切换日可以是 1380 或 1500 分钟；不得固定按 1440 分钟覆盖所有日期。时间统计聚焦于用户实际投入并记录的各类有效活动，不派生计算并展示“其他”未记录时间。

### 示例

某天记录工作 4 小时、学习 2 小时、高质量娱乐 1 小时、低质量娱乐 2 小时、社交 1 小时：

- 已记录总时长为 10 小时。
- 事件性质排行榜依次为工作 4 小时、学习与低质量娱乐各 2 小时、高质量娱乐与社交各 1 小时；并列项按固定事件性质顺序展示。

## 10. 周统计口径

- 周一至周日分别按日统计规则切分和汇总。
- 某事件性质或事件名称的周总时长等于七天对应时长之和。
- 切换周次只改变查询范围，不修改原始时间记录。

## 11. 排行榜规则

### 11.1 按事件性质

- 只包含累计时长大于 0 的事件性质。
- 按累计时长降序；时长相同时按 `work`、`study`、`high_quality_entertainment`、`low_quality_entertainment`、`social` 的固定顺序。
- 每项输出名次、事件性质和精确时长，不计算或展示百分比。

### 11.2 按事件名称

- 将统计范围内规范化后名称相同的记录合并，只包含累计时长大于 0 的名称。
- 按累计时长降序；时长相同时按名称的本地化升序。
- 每项输出名次、事件名称和精确时长，不计算或展示百分比。

并列时仍按上述次级规则生成连续名次，确保页面顺序和自动化测试稳定。

## 12. 时间与时区

- `createdAt`、`updatedAt`、`startAt` 和 `endAt` 应保存为绝对时间点；展示时转换到设备当前时区。
- 周期事件的星期和时刻属于当地日历规则，不应简单当作固定 UTC 时刻保存。
- 用户跨时区后，历史记录按设备当前时区重新归日和分周；不保存或沿用创建时区作为统计边界。
- 所有用户输入的日程和时间记录精确到分钟；番茄钟内部可用秒级剩余时间刷新界面，但设置和统计仍以分钟表达。

## 13. 删除与历史一致性

- 删除普通日程、课程或事件池项目，不应级联删除时间记录。
- 时间记录保存自己的标题和事件性质快照，保证历史统计可重算。
- 删除时间记录必须从应用数据中硬删除，并在确认后立即重算统计；不得通过软删除继续保留可恢复数据。
- 统计查询和名称快捷选项只读取当前存在的时间记录，因此删除的时间和名称都不会残留。
- 灵感使用 `deletedAt` 进入回收站，保留 30×24 小时；普通事件、课程、学期和事件池项目在关系校验与确认后硬删除。
- 硬删除普通事件、课程、学期或事件池项目时同步取消其未来提醒；删除学期前必须先处理引用它的课程，不允许产生悬空引用。

## 14. JSON 备份与导入

### 14.1 备份格式

备份是 UTF-8 明文 JSON，顶层至少包含：

| 字段 | 用途 | 必填 | 约束 |
| --- | --- | --- | --- |
| `formatVersion` | 备份格式版本 | 是 | 当前固定为正整数 `1`；其他版本拒绝导入。 |
| `exportedAt` | 导出时间 | 是 | 绝对时间戳。 |
| `data` | 业务数据快照 | 是 | 包含全部实体、回收站灵感和 `AppSettings`。 |

备份不包含 `PomodoroSession`、通知权限、闹钟权限、签名密钥或设备路径。导出通过系统文件选择器写入用户选择的位置；由于文件可直接读取，导出前必须提示其包含个人数据。

`data` 必须完整包含 `ideas`、`scheduleTasks`、`academicTerms`、`courseSchedules`、`eventPoolItems`、`timeRecords` 六个数组和 `appSettings` 对象。当前导出会写出全部字段；兼容旧备份时，事件池项目缺少 `weight` 自动按 `1` 解析，其他必填字段缺失或出现未知字段仍会被拒绝。可空字段必须显式写为 `null`。绝对时间使用 ISO-8601 UTC 字符串，当地日期使用 `YYYY-MM-DD`，当地时刻精确到分钟，星期使用 `monday` 至 `sunday`，其他枚举使用本文定义的稳定标识。

最小空备份示例：

```json
{
  "formatVersion": 1,
  "exportedAt": "2026-08-25T00:00:00Z",
  "data": {
    "ideas": [],
    "scheduleTasks": [],
    "academicTerms": [],
    "courseSchedules": [],
    "eventPoolItems": [],
    "timeRecords": [],
    "appSettings": {
      "lastFocusMinutes": 25,
      "lastRestMinutes": 5,
      "themeMode": "system"
    }
  }
}
```

### 14.2 导入规则

1. 存在 `running` 或 `paused` 番茄钟时阻止导入，要求用户先结束当前计时。
2. 写入数据库前完整解析并校验 `formatVersion`、字段类型、稳定标识、时间范围、实体引用、学期范围和时间记录重叠；不支持的新版本或任何无效数据都必须拒绝。
3. 校验通过并经用户二次确认后，在单个 Room 事务中整体替换业务数据与回收站；`AppSettings` 在 Room 提交前原子写入 DataStore。设置写入失败会让 Room 回滚，Room 后续失败会补偿恢复原设置，避免形成可见的部分导入。
4. 数据替换前取消旧日程提醒；提交成功后根据导入数据、当前时区和当前系统权限重建未来提醒。
5. 导入不修改 Android 系统权限，也不恢复活动番茄钟。导入后已超过 30×24 小时的回收站灵感应立即永久清理。
6. 提醒重建发生在数据提交后；若系统适配器失败，导入数据保持已提交并向用户明确报告提醒重建失败，不回退为旧业务数据。
